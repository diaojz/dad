# 小红书改编规则

信是写给儿子的；小红书是给陌生人的。改编不是删减，是换一个入口。

## 产出：`xhs/YYYY-MM-DD/post.json`

```json
{
  "title": "≤20 字，小红书标题",
  "cards": [
    {"type": "cover", "kicker": "爸爸的信 · 第N封", "headline": "≤14 字大标题", "sub": "≤24 字副标题"},
    {"type": "body", "heading": "≤12 字", "text": "≤110 字"},
    {"type": "body", "heading": "...", "text": "..."},
    {"type": "action", "heading": "今天做一件事", "text": "≤80 字"},
    {"type": "question", "heading": "爸爸想问你", "text": "≤60 字"}
  ],
  "content": "正文 300–600 字（不放 #标签）",
  "topics": ["爸爸的信", "程序员", "本期主题词"],
  "letter": "letters/xxx.md"
}
```

- body 卡 3–5 张。每张只承载一个推进：场景 → 旧认知为什么曾经对 → 什么变了 → 新做法。
- 标题要具体、有反差，但不能标题党：标题承诺的东西，卡片里必须兑现。
- 正文（content）不是卡片复述：补一个卡片里没讲的细节或出处，结尾邀请评论区回答那个问题。
- 话题写进 `topics` 数组（3–6 个，第一个固定「爸爸的信」），发布脚本会逐个从联想框点选成真话题；正文里写 `#xxx` 平台不认。话题从内容出发（如 #认知升级 #程序员 #终身学习 #父亲的信 + 本期主题词），不蹭无关热点。
- 不写「宝子」「家人们」「绝绝子」，emoji 最多 3 个。
- 卡片图由 `site/build` 的 xhs 渲染器统一出图（信纸风，系列识别度优先），不逐张生图。
